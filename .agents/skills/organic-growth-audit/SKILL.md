# SEO and AEO Organic Growth

Deliver an evidence-based baseline, prioritized implementation, verified changes and a measurable growth plan. Support audit-only, implementation and measurement requests within the user's scope. Preserve customer flows, supplied media, legal terms, credentials and unrelated work.

## Match the workflow to the request

For a narrow audit or measurement request, return the requested evidence and conclusion; do not create files, implement fixes, run builds, prepare deployment or add a growth plan unless those outputs are requested or necessary within the authorized task. A remote-only audit may have no checkout or build identity: mark those not applicable and record the available URL, response and measurement evidence. For an implementation assignment, use the relevant code/build checks; for an authorized publication, also use deployment verification. A full organic-growth assignment warrants the baseline, implementation/review loop and growth plan below.

## Select the relevant guidance

- Before grading or comparing results, read [scoring and measurement](references/scoring-and-measurement.md).
- For research, service pages, FAQs and AI visibility, read [content and answer engines](references/content-and-answer-engines.md).
- For SPAs, multilingual rendering, performance or publishing, read [implementation and delivery](references/implementation-and-delivery.md).
- Before asserting changing platform rules, consult [primary sources](references/primary-sources.md) and verify the relevant live documentation. A dated source check is not a permanent rule.

## Establish the baseline

Identify the requested URLs and site/edition. When repository implementation is in scope, locate the actual checkout, record initial dirty files and active project instructions; confirm the deployment target only when publication is in scope. Inventory routes relevant to the request; a full audit should cover public, private, admin, legal, payment and preview routes and distinguish intentional noindex from accidental exclusions.

Inspect HTTP headers and raw HTML separately from the rendered DOM. Capture status, redirects, title, description, H1, canonical, robots, language, structured data, sitemap and internal links. Probe an unknown URL for a real 404. Do not infer that rendered schema is absent from an empty raw response, or that JavaScript content is universally invisible to Google.

Record environment, timestamp, device and source/build identity. Use one disclosed before/after rubric. Label missing evidence unknown; do not convert an audit opinion into an engine's rating.

## Prioritize and implement

Fix discovery/indexing barriers, inaccurate facts and broken customer journeys first. Then improve useful content, navigation, semantics and experience. Map meaningful intent to existing pages before creating new pages. Word count, keyword variants and a number of FAQs are not quality targets.

Use verified facts and original experience. Keep displayed content, metadata and schema consistent through a shared source where practical. Do not invent prices, reviews, qualifications, dietary safety, meeting locations, accessibility, availability or search demand. Ask only for facts unavailable from authorized sources; continue independent work while they remain pending.

Create real language URLs before reciprocal hreflang. A toggle on one URL is one indexable document. Schema validity, current feature eligibility and observed display are different checks. Search access, AI training access and private-route security are separate decisions. Noindex is not access control.

## Verify and handle findings

For code changes, use the project's production build and meaningful checks. Select checks relevant to the request: raw/rendered parity, direct navigation, fresh/saved language, JS disabled where relevant, mobile/desktop layout, answer/schema consistency and affected interactions. Avoid real orders, payments or customer messages during routine QA.

Diagnose the actual performance bottleneck. Do not disable needed features, weaken security/indexing policies, dilute throttling or cherry-pick runs to satisfy a score. Rebuild after the final product edit and regenerate affected evidence; preserve failed experiments with their status.

When review is required, prepare the scoped diff, protected invariants, exact candidate identity and actual results for the independent reviewer/channel selected by active user/repository policy. This skill does not select a provider or supersede project-specific reviewer rules. An unavailable required reviewer leaves review pending; the implementer cannot certify an independent review. Skill structural validation is not independent product certification.

Triage findings as accepted, disproven with evidence or outside scope. Fix accepted issues and rerun affected checks. Use a bounded loop, typically three rounds for a release; report unresolved blockers instead of certifying a pass. An authorized continuation can open a new scoped investigation with new evidence. Do not run endless score-chasing when progress requires recrawl, field data or owner input.

## Deliver and measure

For a full growth assignment, save the requested baseline, plan, changes, audit log, findings and final evidence in the established project format. For narrower tasks, return only the requested deliverable and save files only when requested or part of the authorized workflow. Report the relevant readiness, lab metrics, field data, index status and organic/AI outcomes separately. For a 100 target, name the instrument, repeat range and remaining uncertainty.

Publish only within existing authorization to the confirmed edition/target. Without publication authorization, finish the concrete artifact and relevant checks before asking for that final action. Skill invocation does not authorize deployment, new accounts/listings, crawler-policy changes, outreach or scheduled monitoring.

After an authorized publication, verify the deployed artifact and relevant flows; reassess with the original rubric when before/after grading is in scope. Produce a 30/60/90-day plan for a full growth assignment or an explicit planning request, not as mandatory output for every audit. Attribute ranking, traffic and citation changes only to observed data; avoid causal claims from one release or one AI answer.
